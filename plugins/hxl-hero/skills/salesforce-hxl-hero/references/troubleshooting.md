# Troubleshooting

Symptoms along the chain, from the deploy to the client. Name the link before changing anything; each fix comes with the check that would have caught it.

| Symptom                                                                                          | Link     | Cause and fix                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Deploy: `Not available for deploy for this organization` on `UiWidgetBundle`                     | Setting  | HXL is off, or the setting was in the same deploy. Deploy `Settings:UiWidget` on its own first ([setup.md](setup.md#turn-hxl-on)); the preflight reports it                                                           |
| Deploy: a Lightning type's `renderer.json` points to a widget that is not deployed               | Deploy   | The widget failed or was not in the deploy - fix the widget's error, deploy widgets and types together                                                                                                                |
| Deploy: `You can't add the items property ...`                                                   | Types    | A list typed as `lightning__listType` in a Lightning type - type it `@apexClassType/c__<Class>$<Inner>` ([lightning-types.md](lightning-types.md))                                                                    |
| Deploy: `There's a problem with your scope(s)`                                                   | Sign-in  | Wrong scope name in `commaSeparatedOauthScopes` - `MCP, RefreshToken`                                                                                                                                                 |
| Deploy: `Enter a valid contact email address`                                                    | Sign-in  | `contactEmail` missing on the External Client App                                                                                                                                                                     |
| Deploy reports conflicts for the External Client App                                             | Deploy   | It was deployed from another folder before; `--ignore-conflicts` once, then keep it in the project                                                                                                                    |
| The client cannot sign in, or the sign-in ends on an error page                                  | Sign-in  | A new External Client App takes up to 30 minutes; the server URL does not match the org type (`/sandbox/`); the client ID is from another org; the client's callback URL is missing                                   |
| The login page says "check your username and password" with the right credentials                | Sign-in  | The browser was forwarded to another org - the address bar shows its My Domain. `sf org open -o <alias>` first, or put the right My Domain into the URL ([auth-and-clients.md](auth-and-clients.md#sign-in-pitfalls)) |
| No failed logins in the org's `LoginHistory` although the user tried                             | Sign-in  | The attempts went to another org or the email field. Use **Log In with Username**                                                                                                                                     |
| Connected, but no tools - or a tool says it has no access to an Apex class                       | Access   | The user's permission set lacks `classAccesses` for the tool class                                                                                                                                                    |
| Tools listed, but the answer has no widget                                                       | Server   | The server is not active (`McpServerAccess`), `uiResource` does not match a `resourceName`, or the client does not render MCP Apps                                                                                    |
| "Couldn't render a rich UI for this response, please check out the text response returned."      | Call     | Several requests in one call - the widget renders one result. Ask again for one; add "exactly one request per call" to the tool description ([mcp-server.md](mcp-server.md#tool-descriptions))                        |
| A tool call fails with `JSON_PARSER_ERROR` / "entity body is required"                           | Call     | Arguments without the `inputs` wrapper - `{ "inputs": [ { ... } ] }`                                                                                                                                                  |
| The widget renders, but empty or without some values                                             | Renderer | A renderer binding without `outputValues`, a missing binding, or an attribute name that differs between renderer, widget schema and widget - the checker reports each                                                 |
| A part of the widget never shows                                                                 | Widget   | `meta.if` on a non-boolean; a binding to an attribute that is not in `schema.json`                                                                                                                                    |
| A button is greyed out                                                                           | Widget   | `tile/button` without `actions.click`                                                                                                                                                                                 |
| A changed tool description has no effect                                                         | Client   | The hosted server picks it up after about two minutes, the client per conversation - start a new one                                                                                                                  |
| A changed widget still looks old                                                                 | Client   | The client keeps the rendered resource for a while - start a new conversation                                                                                                                                         |
| Dates in an unexpected format                                                                    | Apex     | Apex formats in the asking user's locale and time zone; that is right. Set the test user's locale for screenshots                                                                                                     |
| Lightning: the header has no Agentforce icon                                                     | Access   | The user misses the project's permission set with `agentAccesses`. There is no error message ([agentforce-channel.md](agentforce-channel.md#access))                                                                  |
| Lightning: the agent answers in text without a widget                                            | Agent    | The output is not one object with `complex_data_type_name` and `is_displayable: True`, or an older version is active: check that the publish worked, then start a new conversation                                    |
| Lightning: the agent is on an older version after a setup                                        | Agent    | `sf agent activate --json` without `--version` picks the latest version that is not active. Name the version ([agentforce-channel.md](agentforce-channel.md#shipping-it))                                             |
| `sf agent preview --authoring-bundle`: `Cannot read properties of undefined (reading 'replace')` | Agent    | The CLI reads `default_agent_user`, which an employee agent does not have. Preview the published agent with `--api-name`                                                                                              |
| A deploy wants to delete a permission set that moved out of the package directory                | Deploy   | Source tracking still knows the file in a scratch org. `sf project reset tracking`, then deploy changed folders with `--source-dir`: after the reset, a plain deploy treats them as unchanged                         |
