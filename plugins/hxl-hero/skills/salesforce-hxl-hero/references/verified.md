# Verified in an org

What Polyglot Arcade v1.1.0 verified in scratch orgs on Winter '27 (API 67.0 and 68.0), October 2026, and what the official documentation of that release did not say. Every line is a fixed point, not the current truth - check it again when a step fails on a later release, and update the project's docs with what you find.

## Turning HXL on

- The setting is `Settings:UiWidget` - `UiWidgetSettings` with the field `hxlEnabled`. In a scratch org definition: `"settings": { "uiWidgetSettings": { "hxlEnabled": true } }`.
- Before the setting is on, the org does not list the metadata type `UiWidgetBundle` at all. `LightningTypeBundle`, `McpServerDefinition` and `ExternalClientApplication` are listed regardless.
- A deploy that contains the setting **and** widgets fails with `Not available for deploy for this organization` on every `UiWidgetBundle` file: the org checks the widgets before it applies the setting. Deploy `Settings:UiWidget` on its own first.

## Lightning types and widgets

- Widgets and Lightning types deploy together in one deploy; the Metadata API orders the widget before the type that references it. Deploying them separately: widgets first.
- Lists in an Apex response are bindable as a top-level output (`List<Inner>` on a `@InvocableVariable`); the response type types them `@apexClassType/c__<Class>$<Inner>` and the renderer binds them with two segments, `{!$attrs.outputValues.<list>}`. Global inner classes with `@AuraEnabled` fields work.
- `FORMATNUMBER(<number>)` printed `3310`, without a thousands separator, in the MCP renderer.
- A widget renders in the client's theme (light or dark) from the host context.

## The MCP server

- `McpServerDefinition` has no active flag. Setup's **Activate** creates a Tooling API record `McpServerAccess` (`DeveloperName`, `MasterLabel`, `Active`, `McpServerId`); a script can create it or set `Active = true`.
- The server definition can be written from scratch and deployed - no need to create it in Setup first. The tool's API definition for an Apex action: `apiSource` `API_CATALOG`, `apiIdentifier` `aa:apex-<Class>`, `operation` `<Class>`.
- Server URLs: `https://api.salesforce.com/platform/mcp/v1/custom/<server>` for production and developer orgs, `.../v1/sandbox/custom/<server>` for sandboxes **and scratch orgs** (they report `Organization.IsSandbox = true`). The protected-resource metadata at `https://api.salesforce.com/.well-known/oauth-protected-resource/platform/mcp/v1/[sandbox/]custom/<server>` names `login.salesforce.com` or `test.salesforce.com` as the authorization server.
- The tool's input schema wraps the action's input: `{ "inputs": [ { ... } ] }`. Unwrapped arguments fail with `JSON_PARSER_ERROR`.
- A call with several entries in `inputs` returns all results, but the widget renders none: the MCP App shows "Couldn't render a rich UI for this response, please check out the text response returned." Claude did bundle periods on its first try; a tool description that asks for exactly one request per call fixed it.
- A changed tool description reached `tools/list` of the hosted server after about two minutes.
- A user without access to the tool's Apex class gets an empty `tools/list`, and a call fails with `You don't have access to the Apex class`. `classAccesses` in the users' permission set fixes it.
- The `ui://` resource is an MCP App of about one megabyte - Salesforce's widget renderer - with a CSP for the org's domain. The tool result carries `structuredContent` and `_meta["salesforce/uiMetadata"]` with the resolved widget tree.

## Sign-in

- An External Client App deploys as metadata into scratch orgs, although Setup cannot create one there: `ExternalClientApplication`, `ExtlClntAppConfigurablePolicies` (`isEnabled`, `isOauthPluginEnabled`), `ExtlClntAppOauthSettings`, `ExtlClntAppGlobalOauthSettings`, `ExtlClntAppOauthConfigurablePolicies`.
- OAuth scope names in `commaSeparatedOauthScopes`: `MCP` and `RefreshToken` (an invalid name lists all valid ones in the deploy error).
- `ExtlClntAppGlobalOauthSettings`: `callbackUrl`, `isPkceRequired`, `isNamedUserJwtEnabled` (JWT-based tokens for named users), `isConsumerSecretOptional`. `contactEmail` on the app is required.
- The consumer key is generated by the org; retrieve `ExtlClntAppGlobalOauthSettings:<name>` to read it. A later deploy without `consumerKey` in the file keeps it.
- The login page of `test.salesforce.com` starts with "Log In with Email"; scratch org usernames (`test-...@example.com`) need **Log In with Username**, then the password in a second step. New users land on "Register Your Mobile Phone" - skippable.
- `test.salesforce.com` forwards to the My Domain used last in that browser. A user with several scratch orgs lands in the wrong one and gets "check your username and password"; opening the right org first (`sf org open -o <alias>`) fixes it.
- A PKCE authorization-code flow against the org with the External Client App's consumer key, `scope=mcp_api refresh_token` and the client's callback returned a JWT access token and a refresh token.
