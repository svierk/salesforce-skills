# Sign-in and clients

MCP clients sign the user in with OAuth 2.0 against an External Client App in the org. Every tool call then runs as that user - the reason the widgets show what the user may see, and nothing more.

## The External Client App

Five metadata files, all deployable - also into scratch orgs, where Setup cannot create an External Client App:

| Folder                        | File                                    | Holds                                                                                               |
| ----------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `externalClientApps/`         | `<eca>.eca-meta.xml`                    | `label`, `description`, `contactEmail` (required), `distributionState` `Local`, `isProtected` false |
| `extlClntAppPolicies/`        | `<eca>_plcy.ecaPlcy-meta.xml`           | `isEnabled` true, `isOauthPluginEnabled` true                                                       |
| `extlClntAppOauthSettings/`   | `<eca>_oauth.ecaOauth-meta.xml`         | `commaSeparatedOauthScopes` `MCP, RefreshToken`                                                     |
| `extlClntAppGlobalOauthSets/` | `<eca>_glbloauth.ecaGlblOauth-meta.xml` | `callbackUrl`, `isPkceRequired` true, `isNamedUserJwtEnabled` true, `isConsumerSecretOptional` true |
| `extlClntAppOauthPolicies/`   | `<eca>_oauthPlcy.ecaOauthPlcy-meta.xml` | `permittedUsersPolicyType` `AllSelfAuthorized`, `ipRelaxationPolicyType`, `refreshTokenPolicyType`  |

- **The scopes** are `MCP` (shown as `mcp_api`) and `RefreshToken`. A wrong name fails the deploy with the list of valid names.
- **PKCE and no secret** - desktop and web clients like Claude use a public client with PKCE; JWT-based tokens for named users as the Hosted MCP guide asks.
- **The callback URL** belongs to the client: Claude `https://claude.ai/api/mcp/auth_callback`; ChatGPT shows its own per connector; Slack's Manual OAuth names its own. Several clients: several URLs, comma-separated - read the field's format in the guide for the release.
- **`contactEmail`** is required. Use a team or placeholder address, never a person's private address in a public repository.
- **The consumer key** - the OAuth client ID - is generated by the org. Retrieve `ExtlClntAppGlobalOauthSettings:<eca>_glbloauth` into a folder outside the project and read `consumerKey`; a later deploy without it in the file keeps it. It is public; do not commit it anyway - it is org-specific.
- **Stricter options** from the guide: require a permission set for pre-authorization, IP ranges, refresh token validity and rotation, single logout. Offer them for anything beyond a demo.
- A new External Client App can take up to 30 minutes before sign-in works.

## Clients

| Client   | Connect                                                                                                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Claude   | claude.ai or the desktop app: **Customize → Connectors → Add custom connector**, the server URL, **Use your own OAuth client** with the client ID, no secret, then **Connect**. Claude Code inherits the connector |
| ChatGPT  | A connector with the server URL and client ID; add the callback URL ChatGPT shows to the External Client App                                                                                                       |
| Slackbot | Add the MCP server in Slack with **Manual OAuth**, the server URL and the client ID. Widgets do not render when the server returns Block Kit                                                                       |

Then sign in as a user with the permission set and ask a question the tool answers. Start a new conversation after changing a tool description.

## Sign-in pitfalls

- **The wrong org.** `test.salesforce.com` forwards to the My Domain used last in that browser. With several scratch orgs, open the right one first - `sf org open -o <alias>` - and connect again; or replace the host in the login URL with the org's My Domain and keep the rest.
- **"Log In with Email".** The login page starts with an email field; scratch usernames like `test-...@example.com` are not emails. Choose **Log In with Username**; the password comes in a second step.
- **A scratch admin has no password.** `sf org generate password -o <alias>` sets one; show it only to the user who asked, for their own org.
- **Registration screens** ("Register Your Mobile Phone") for new users can be skipped.
- **Production and Developer Edition** sign in at `login.salesforce.com` - the URL without `/sandbox/`.
